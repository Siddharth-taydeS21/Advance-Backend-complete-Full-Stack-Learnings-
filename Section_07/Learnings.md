## Lecture 1, 2 - CPU operations vs I/O operations 

### CPU operations

CPU operations are the tasks which spend the most time performing arithmetic calculations, logics, or Data transformations using the CPU. These tasks are really dependent on the clock rate, speed, and the number of CPU cores. They highly utilize CPUs for heavy computing tasks. 

Primary examples of CPU operations includes 
- video or image resource rendering, 
- Cryptographical hashing And encryption/decryption, 
- machine learning model training, and scientific calculations and 
- Heavy sorting algorithm/Metrics traversal or Inversions  

### I/O operations

I/O operations are the tasks which spend the most time waiting for other external systems or for data to get transferred, rather that computing. They do not utilize the CPU very heavily compared to computing tasks or CPU operations. 

The speed of these tasks varies heavily on the speed of HDDs or SSDs, databases, or the network connection. 

Primary examples of I/O operations includes 
- querying a remote database, 
- Making HTTP or API requests to an external server, 
- writing or reading disk files directly on the disk, 
- waiting for user input in GUI applications 

### Asynchronous I/O of Node.js 

Node.js achieves high-performance async I/O by delegating the non-blocking tasks to the operating system or to the worker thread pool, which is created or managed by C++ **libuv** Library. 

- For standard network protocol or network requests that uses the local resources of the operating system, such as `kernel` or other shells. 
- For the other kind of non-blocking operations which lacks native OS support, such as CryptoGraphy or Encryption/decryption, It hands over that kind of non-blocking and heavy task to the worker thread pool, which is managed by the libuv library by C++.

## Lecture 3 - Event Driven Architecture of Node.js

Event-driven architecture in Node.js is a design pattern which tells the overall Node.js flow to do something when a particular event occurs, such as outputs of sensors, user inputs or messages from other programs. 

Node.js, on a low level, has the architecture of a non-blocking event loop, which runs infinitely in a single-threaded non-blocking way and can handle multiple concurrent processes without even waiting for I/O applications to be finished. 

--- 

There are three main components of event-driven architecture -   
**Event emitter** ->  **Event listener** -> **Event handler**.

**Event emitter:**   
An event emitter can be anything. It can be input by a user, or a message from another program, or output of another I/O device. Event emitters are the physical or virtual things which cause an event to occur. 

**Event listener:** 
Event listeners can be programs or functions which listen for the occurred event, which is generated by event emitters. 

**Event handler:**  
An event handler is the core application logic or a chunk of logic where we can decide what actions to be performed on a particular event in a programmatic way.

## Lecture 4, 5 - EventEmitter class in Node.js

In Node.js `EventEmitter` is a core class which drives the platform's asynchronous and event-driven architecture. With the help of that class we can emit named events which can act as triggers. After triggering them they will execute the registered callback handlers. 

**How it works -**

- **emitter.on(event, handler)** -

With the help of the `.on()` method we can register a named event with its callBack handler. We can add multiple handlers on a single event. Later we can use `emitter.emit()` method to trigger and execute the events and their registered callbacks. 

- **emitter.emit(event);** -

With the help of the `emitter.emit()` method we can trigger a particular named event and execute the callback function which is registered with that named event. 

- **emitter.once(event);** -

If there are multiple calls of a named event in our program, with the help of the `emitter.once()` method, we can prevent repetitive calls of a single event and we can call or trigger that event just one time. 

- **emitter.setMaxLength(number);** - 

With the help of `emitter.setMaxListeners`,  
we can define how many handlers a single main event can hold.
